HOPKINS — STRUCTURAL AUDIT (for the next refactor stage)
========================================================
Date: 2026-06-29
Scope: overall code structure, not feature bugs. Every item below is backed by a concrete
location. Severity: [H]=high, [M]=medium, [L]=low. This is a map for a future session that
will perfect the code in a fresh directory — it is intentionally directional, not prescriptive
(no rewrites here).

WHAT IS ALREADY GOOD (don't undo these)
---------------------------------------
- SQL is parameterised everywhere (no string-built queries with user input) -> no SQL injection.
- The physics engine now has a single source of truth: ModelGPX.py removed; the repeated
  Peucker-Douglas border logic is one helper (compute_section_borders), the power profile is
  one helper (interp_power), the route section table is one inner builder (build_sections).
- Template URLs are now relative (no hardcoded host); requirements.txt is pinned; physics_engine.txt
  documents the engine; a working Playwright E2E harness exists.


1. ARCHITECTURE / SEPARATION OF CONCERNS
----------------------------------------
[H] app.py is a 1481-line monolith mixing four unrelated layers:
      - FIT/GPX parsing & geometry        (extract_data, make_segments, gpx_* , distgrad_gpx)
      - physics engine                    (cda, power, solve_cubic_speed, calculate, model, ...)
      - database access                   (init_db + 22 inline sqlite3.connect blocks)
      - web layer                         (~30 Flask routes)
    Suggested target layout for the new directory:
      hopkins/
        __init__.py            app factory: create_app()
        config.py              secret key, DB path, upload dir, maps key  (from env)
        db.py                  connection helper + schema/migrations
        physics/parsing.py     fit/gpx -> points/segments
        physics/cda.py         segment CdA measurement
        physics/route.py       power model + route estimation
        web/auth.py            login/register/logout  (blueprint)
        web/activities.py      upload/history/visualise/segments (blueprint)
        web/routes_gpx.py      routes/view_route/calculate_route/toptube (blueprint)
        templates/ , static/
[M] No application factory and no blueprints: a module-level `app` is built at import time, so
    the app can't be configured per-environment or imported cleanly for tests. Move to
    create_app() + register_blueprints().
[L] view_tables.py is a throwaway debug script at the repo root — move to scripts/ or drop.


2. TEMPLATES
------------
[H] No template inheritance at all (0 `{% extends %}`, 0 `{% block %}`). The nav bar is
    copy-pasted into 12 templates (grep: `page_permissions[role`). Introduce base.html with a
    {% block content %} and a _nav.html partial; every page extends base. This alone removes the
    single largest source of HTML duplication.
[M] The `role` contract is inconsistent and fragile: most templates call `page_permissions[role()]`
    (role passed as the fetch_role *function*), but home.html uses `page_permissions[role]` (role
    passed as a *string*), and f_home passes a string while ~9 other routes pass the function
    (app.py:757 vs 774, 873, ...). Pick ONE: compute the role string once (ideally in the app
    factory / context processor) and pass it everywhere. Today this is a latent KeyError.
[M] Dead templates present but never rendered by app.py: calculate.html, edit.html, hmm.html,
    index.html, kill.html, launch.html. Verify and delete (left in place this session because
    reachability wasn't 100% proven).
[M] Page chrome (fonts, CSS links, the Google Maps loader) is repeated per file; a base template
    would centralise it. A Jinja context processor could inject page_permissions/page_titles/role
    so every render_template() stops passing them by hand (they appear in ~10 calls).


3. DATABASE LAYER
-----------------
[H] 22 separate `sqlite3.connect('templates/data.db')` blocks, each repeating
    connect/cursor/execute/fetch/close. Many don't close on exception (no try/finally or context
    manager). Introduce one get_db()/with-connection helper (or Flask `g` + teardown) and route all
    access through it.
[M] The database file lives INSIDE the templates directory (templates/data.db) and is addressed by
    a relative path, so behaviour depends on the process CWD and the data sits next to the views.
    Move it to a data/ dir and make the path configurable.
[M] "Migrations" are `try: ALTER TABLE ... except Exception: pass` inside init_db (app.py ~line
    120-135). That silently hides real errors and isn't versioned. Use an explicit, ordered
    migration step or a tiny schema-version table.
[L] users.credit looks unused (set to 100 on register, never read). Confirm and remove, or wire up.


4. AUTHENTICATION / AUTHORISATION  (structural, with security impact)
--------------------------------------------------------------------
[H] No login enforcement anywhere: no before_request, no login_required decorator. 7 routes read
    `session['username']` directly, so an anonymous request to /history, /upload, /routes, etc.
    raises KeyError -> 500 instead of redirecting to /login. page_permissions exists but is ONLY
    used to render the nav; it is never checked server-side. Add a login_required decorator (or a
    blueprint before_request) and enforce it.
[H] Insecure direct object references (horizontal privilege escalation). Data routes trust
    client-supplied IDs instead of scoping to the session user:
      - f_visualise / f_view_segment      : user & id come from the `q` token (app.py:899, 1105)
      - f_delete_file / f_delete_segment   : delete by id from the form, no ownership check (1297, 1172)
      - f_calculate_route                  : user/id_route from the form (1345-1346)
    `encode_q`/`decode_q` is plain base64 (NOT signed), so a logged-in user can craft any q and
    read/delete another user's activities, segments and routes. Fix direction: derive id_user from
    the session, scope every query with `WHERE id_user = ?`, and either sign the token or drop it
    in favour of ids + ownership checks.
[M] Config secrets / hardening:
      - app.secret_key = 'secret'  (app.py:12)  -> move to env; sessions are forgeable as-is.
      - app.run(debug=True)        (app.py:1482) -> never in prod (Werkzeug debugger = RCE).
      - CORS(app)                  (app.py:11)   -> wide open; scope to needed origins or remove.
      - Google Maps API key `AIzaSyDUAk339DGU-IlM7XDkLa-WLRWYNBhVuY0` is hardcoded in 5 templates.
        Inject it from config and restrict the key by HTTP referrer in the Google console.


5. ERROR HANDLING
-----------------
[M] 4 bare `except:` clauses (e.g. parsing/migration paths) swallow everything including
    KeyboardInterrupt/SystemExit and hide real failures. Catch specific exceptions; log the rest.


6. REMAINING PHYSICS DUPLICATION / SMELLS
-----------------------------------------
[M] The 8-way gradient bucketing (`if segment[1] < -30 ... elif < 0 ... else 7`, plus the `low`
    flag) is copy-pasted in calculate() and get_power() (14 lines total, app.py ~384-408 and
    ~626-652). Extract `grade_rank(grade_permille) -> (rank, is_low)` and call it from both. This
    is the last big copy-paste in the engine after this session's cleanup.
[L] Local variable `cda` shadows the module-level function `cda()` inside calculate()/get_power()/
    f_calculate (app.py:431, 433, 654, 656, ...). Rename the local to `cda_val` to avoid confusion.
[L] `parameters` is overloaded: sometimes a 2-element list [iduser, idactivite] passed to templates,
    sometimes the physics `parameter()` object. Rename one of them.
[L] Route handler names are inconsistent: f_* for most, go_to_login/go_to_register for two GET
    pages. Standardise once routes move into blueprints.


7. REPO HYGIENE / TOOLING
-------------------------
[H] Not a git repository, no .gitignore, no tests, no README. The next directory should start with
    `git init`, a .gitignore, a minimal README (how to run), and at least smoke tests around the
    physics (the E2E harness from this session is a good seed).
[M] Large binary backups committed at the root: static.zip (2.1 MB) and templates.zip (3.4 MB).
    Remove from the tree (or .gitignore) — they look like snapshots, not dependencies.
[M] OS cruft committed: .DS_Store (x4) and templates/Thumbs.db. Add to .gitignore and delete.
[M] templates/uploads/ holds real user/test data (FIT/GPX files + a copy of data.db) mixed in with
    the Jinja templates. Move uploads out of templates/ to a top-level, git-ignored data dir.
[L] Hardcoded paths ('templates/data.db', 'templates/uploads') are scattered through the routes —
    centralise in config.py once the package split happens.
